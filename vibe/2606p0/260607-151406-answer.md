## 结论摘要

- 已确认：本仓库已有“只按用户已启用选项记录/发送”的机制。你使用 Custom URL 时，核心开关是中文界面里的 `记录细节` -> `记录到自定义 URL`；如果还使用批量补发，则是 `自动发送、发电子邮件和上传` -> `允许自动发送` + `自动发送目标` -> `自定义 URL`。
- 已确认：Custom URL 已有离线队列。`丢弃离线位置` 关闭时，离线请求会排队，恢复联网后发送；`丢弃离线位置` 打开时，离线点不会入队。
- 已确认：Custom URL 补推点的时间可以保持记录时的时间。实时 Custom URL 请求序列化的是基于原始 `Location` 格式化后的请求；批量 Custom URL auto-send 从 CSV 恢复 `Location.setTime(...)`，请求模板 `%timestamp`、`%time` 使用记录时间。
- 需要开发：App 内“过去一段时间轨迹地图视图”和“为地图查询保留本地轨迹缓存一段时间”当前没有内置实现。现有项目提供 simple/detailed/log/big/annotation 五个视图，不含地图视图；官网也把轨迹文件的地图查看描述为通过 Google Earth、Google Maps 等外部工具处理。
- 建议方案：新增独立的 `TrackCache` 本地缓存，不依赖用户是否启用 GPX/CSV；新增“本地轨迹保留时间”设置；新增 `TrackMapViewFragment`，按用户选择的 5/10/15/30/60 分钟时间段切割轨迹并用不同颜色展示。

## 官方已有能力与配置方式

### 1. Custom URL 联网发送配置

已支持，不需要开发。

配置方式：

- 实时逐点发送：进入 `记录细节`，启用 `记录到自定义 URL`，在 `自定义 URL` 设置页里配置 `URL`、`HTTP 方法`、`HTTP 头`、`HTTP 内容`、`基础认证`。
- 断网后仍保留每个点等待补推：在 `自定义 URL` 设置页里保持 `丢弃离线位置` 为关闭状态。这个开关打开时，中文摘要是“仅在网络连接可用时将位置记录到自定义 URL（不影响自动发送）”，也就是离线点会被丢弃。
- 批量补发 CSV 每一行：进入 `自动发送、发电子邮件和上传`，启用 `允许自动发送`，设置 `发送频率`，在 `自动发送目标` 中只启用 `自定义 URL`。代码会自动启用 `记录到 CSV 日志`，并按 CSV 每一行生成一个 Custom URL 请求。
- 如果只想 Wi-Fi 发送，启用 `仅在 Wi-Fi 环境下发送`。徒步旅行中如果经常只有蜂窝网络，建议不要启用这个开关，否则补推会等到 Wi-Fi。

为了确保“只走 Custom URL”，应保持其他发送目标关闭，例如 OpenStreetMap、Google云端硬盘、Dropbox、SFTP、FTP、私有云存储、电子邮件、OpenGTS。记录格式方面，若只需要 Custom URL 实时发送，可以只启用 `记录到自定义 URL`；若使用 Custom URL 批量自动发送，需要保留 `记录到 CSV 日志`。

边界：本配置只表示“本 App 的记录/发送链路”；Android 系统定位服务、底图加载、第三方地图 SDK 未来引入后的网络行为需要单独约束。

### 2. Custom URL 断网缓存、恢复联网补推、保留记录时间

已支持，但分两种模式：

- 实时逐点 Custom URL：每个记录点会格式化成一个 WorkManager 任务。断网时任务因网络约束等待；恢复联网后执行。只要 `丢弃离线位置` 关闭，就不会因为当下离线而直接跳过。
- 批量 Custom URL auto-send：`自定义 URL` 自动发送会从 CSV 文件逐行生成请求。CSV 中 `timestamp_ms` 是记录时的毫秒时间；恢复成 `Location` 后再替换 `%timestamp`、`%time`、`%date`、`%timeoffset`。

服务端建议：URL 或 body 中显式带上 `%timestamp` 或 `%time`，服务端以这个字段做幂等去重。批量自动发送可能因为同一 CSV 文件重复发送而出现重复请求，这属于现有机制边界。

如果需求定义为“App 内可查看每个待补推点、每次请求成功/失败状态、手动重试/删除”，当前 Custom URL 机制还不是完整 Outbox，需要另做队列表；如果只是“断网恢复后补推，且补推使用原始记录时间”，当前已有能力基本满足。

## 需要开发的能力

### A. 本地轨迹缓存保留时间

目标：

- 记录到的有效点，除了按用户配置写文件或发送外，还写入 App 本地轨迹缓存。
- 缓存保留一段时间，供断网时查看最近轨迹。
- 缓存与 GPX/CSV 开关解耦：即使用户只启用 `记录到自定义 URL`，也能在地图视图里看到最近轨迹；如果启用 Custom URL 自动发送导致 CSV 被打开，也不把 CSV 作为地图查询的主数据源。

推荐设置：

- 新增设置项：`本地轨迹保留时间`。
- 建议中文界面放在 `记录细节` 或新增 `轨迹地图` 设置分组中；名称使用中文，不使用英文 `Track cache`。
- 候选值：`1小时 / 3小时 / 6小时 / 12小时 / 24小时 / 3天 / 7天`，默认 `24小时`。
- 关闭选项不建议默认提供；如果要提供，应明确提示关闭后地图历史轨迹不可用。

数据职责：

- `TrackCacheRepository`：接收通过现有过滤后的有效 `Location`，落盘为结构化点。
- `TrackCacheCleaner`：按保留时间清理过期点，在 App 启动、每次插入、打开地图视图时触发。
- `TrackPoint` 字段：记录时间、经纬度、海拔、精度、速度、方向、provider、卫星数、HDOP/VDOP/PDOP、注释、profile、文件名、累计距离、写入时间。

存储取舍：

- 推荐 SQLiteOpenHelper，不引入 Room，保持 Java 项目和现有依赖风格，便于按 `recorded_at` 范围查询。
- 不建议直接解析 GPX/CSV 作为地图数据源。原因：用户可能关闭这些格式；跨文件模式、CSV 分隔符和大文件解析会让地图打开变慢。

异常处理：

- 缓存写入失败不应阻断现有文件记录和发送链路，但需要写 debug log，并通过非阻塞通知提示“轨迹缓存写入失败，地图历史可能不完整”。
- 磁盘空间不足时优先执行过期清理；仍失败则跳过本点缓存，不影响已有日志文件。

### B. 地图轨迹视图

目标：

- 新增主界面视图：中文名称建议 `轨迹地图`。
- 展示本地缓存中“保留时间范围内”的轨迹。
- 用户可配置切割粒度：`5分钟 / 10分钟 / 15分钟 / 30分钟 / 60分钟`。
- 按自然时间边界切段并用不同颜色展示。

切段规则：

- 用记录时间 `recorded_at`，不是插入时间或补推时间。
- 边界按自然钟点对齐：`floor(recorded_at / segmentMillis) * segmentMillis`。
- 示例：粒度 15 分钟，轨迹 13:12 到 13:33，切为 `13:12~13:15`、`13:15~13:30`、`13:30~13:33`。
- 若相邻两个点跨越边界，展示层可插值一个边界点，只用于绘制颜色切换，不写回缓存。

地图 SDK 取舍：

- 推荐 `osmdroid`：开源、无 Google Play Services 依赖、适合 F-Droid 分发，能利用瓦片缓存。
- 断网时底图不能保证完整；地图视图必须在无底图瓦片时仍绘制轨迹线、当前位置和比例尺。后续再考虑离线 MBTiles/离线区域下载。
- 不建议 Google Maps SDK：需要 API key 和 Google Play Services，不符合当前项目无 Google 地图依赖的风格。

交互范围：

- 首屏显示最近轨迹并自动缩放到轨迹边界。
- 支持定位到最新点、缩放、刷新。
- 图例显示每段起止时间与颜色；颜色使用固定调色板循环，避免随机导致同一时间段多次打开颜色不一致。
- 断网状态只影响底图加载，不影响轨迹查询和绘制。

性能边界：

- 查询只取保留窗口内点，并限制一次渲染点数。超过阈值时按像素/时间抽稀，但保留首尾点和分段边界点。
- 地图页面不解析 GPX/CSV 大文件，避免徒步多日后打开卡顿。

## 建议实施步骤

1. 增加偏好项和默认值：本地轨迹保留时间、地图切段粒度。
2. 增加本地缓存表和 Repository，只在 `GpsLoggingService` 已接受一个点并准备写入时追加缓存。
3. 增加过期清理，确保不会无限占用磁盘。
4. 增加轨迹查询与切段逻辑，先用单元测试覆盖 13:12~13:33/15 分钟等边界例子。
5. 增加地图视图入口：`gps_main_views`、`GpsMainActivity.loadFragmentView()`、新 Fragment 和布局。
6. 接入 osmdroid 或同等开源地图控件；实现无网络底图降级。
7. 做端到端验证：断网记录、打开地图、恢复联网补推、检查服务端收到的时间字段仍为记录时间。

## 副作用与兼容性

- 存储：新增缓存会增加磁盘占用，但通过保留时间控制上限；默认 24 小时对徒步场景较实用。
- 隐私：缓存会让 App 在本地保留更多近期轨迹。设置文案需要明确“仅保存在本机，超期删除”。
- 上传链路：新增地图缓存不改变现有 GPX/CSV/Custom URL/OpenGTS/Auto send 语义。
- 电量：缓存写入是本地轻量操作；地图视图打开时底图加载和渲染会耗电，记录后台不应主动刷新地图。
- 兼容：新增地图依赖要确认 minSdk、F-Droid 构建、GPL 兼容性；不应引入闭源 SDK。
- 中文界面：新增设置、视图名称、错误提示优先补 `values/strings.xml` 和 `values-zh-rCN/strings.xml`，不要只写英文资源。
