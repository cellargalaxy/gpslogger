## 任务结论

已确认本次安装报“软件包似乎无效”的高概率原因在 fork 专用构建流水线：旧版 `.github/workflows/fork-build-apk.yml` 在缺少 `KEYSTORE_BASE64 / SIGNING_KEY_ALIAS / SIGNING_KEY_PASSWORD / SIGNING_STORE_PASSWORD` 任一 secret 时，会继续产出未签名 release APK。Android 不能安装 unsigned APK。

本轮已修复为：

- secrets 齐全：继续构建 `assembleRelease`，发布 `gpslogger-travel-release-...apk`。
- secrets 缺失：不再构建/发布 unsigned release，改为构建 `assembleDebug`，发布 `gpslogger-travel-debug-...apk`，作为可安装的测试包。
- Release 发布前清理旧 workflow 可能留下的 `-unsigned` 资产，避免用户误下载旧无效包。
- 文档补充：Actions artifact 下载的是 zip，需要解压后安装里面的 `.apk`；Release 页面下载的 `.apk` 才能直接安装。

## 方案取舍

- 不选择“继续发布 unsigned APK 并提示用户不要安装”。原因：用户最容易从 Release 页面直接下载最新资产，保留 unsigned 资产会继续制造同类安装失败。
- 不在仓库里内置公共 release keystore。原因：公共 keystore 会让测试包看起来像 release 包，但签名私钥公开，不适合作为正式发布身份。
- 选择 debug-signed fallback。原因：无需 secrets，Android 可安装，满足个人 fork 自测；缺点是 debug 签名不适合正式分发，且不同签名的旧版本不能覆盖安装。文档已要求正式 release 配置 keystore secrets。

## 已实施改动

### `.github/workflows/fork-build-apk.yml`

- 修改 workflow 注释和 `workflow_dispatch` 描述，明确无 secrets 时是 `debug fallback`，不是 unsigned release。
- `build-release` job 中：
  - secrets 齐全时仍执行 `./gradlew :gpslogger:assembleRelease --no-daemon --stacktrace`。
  - secrets 缺失时执行 `./gradlew :gpslogger:assembleDebug --no-daemon --stacktrace`。
- `Locate packaged APK` 根据 `have_keystore` 选择：
  - `gpslogger/build/outputs/apk/release`，产物类型 `release`，签名状态 `release-signed`。
  - `gpslogger/build/outputs/apk/debug`，产物类型 `debug`，签名状态 `debug-signed`。
- 增加 `Remove old unsigned release assets`，在 tag/nightly Release 发布前删除旧 `-unsigned` 资产。
- Release body 增加构建类型、签名状态和 debug-signed 安装注意事项。

### `.github/workflows/README.md`

- 更新构建产物说明：signed release 与 debug-signed fallback 都可安装，旧 `-unsigned.apk` 不可安装。
- 明确 Actions artifact 是 zip，需解压后安装 `.apk`。
- 明确没有配置 keystore secrets 时应下载 `gpslogger-travel-debug-...apk`。
- 增加“软件包似乎无效”排错说明。

## 副作用与兼容性

- 已有签名 secrets 的正式 release 链路不变，仍走 `assembleRelease` 和 release keystore。
- 未配置 secrets 的 tag/nightly Release 将不再出现 `gpslogger-travel-release-...-unsigned.apk`，而是出现 `gpslogger-travel-debug-...apk`。
- debug-signed fallback 只能作为测试包。若手机已安装过不同签名的 GPSLogger，需要先卸载旧版本；若需要后续稳定覆盖安装，应配置固定 keystore secrets。
- 旧 nightly Release 里如果已经存在 `-unsigned` 资产，新 workflow 下次运行会尝试删除这些资产；如果没有既有 Release，该清理步骤会直接退出，不阻塞创建 Release。
