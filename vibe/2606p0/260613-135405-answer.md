生成时间：2026-06-13

## 任务目标

修复点击「清除全部地图缓存」后地图缓存没有真正清除的问题。用户现象包括：断网并杀应用后仍能加载出地图，且「已缓存地图文件大小」显示不变。

## 根因分析

已确认的问题点：

1. 旧 `deleteAll()` 只删除 MapLibre offline regions 后调用 `clearAmbientCache()`。MapLibre 文档明确 `clearAmbientCache` 只针对 ambient cache，并且不会影响与 offline region 重叠的资源；因此它不是「清除全部地图缓存」的强语义 API。
2. 旧 `clearAmbientCache()` 和 `enableAmbientCacheRetention()` 通过反射调用 MapLibre 公共 API。当前 debug 构建开启 `minifyEnabled true`，反射调用即使失败也只记录日志，用户侧会表现为点击后无实际变化。
3. 旧 `totalBytes()` 只扫描 `cacheDir`、`filesDir`、`noBackupFilesDir` 和 database 目录，并按文件名特征统计。MapLibre `FileSource` 有明确的 resources/internal cache path，统计应直接纳入这些路径，避免路径配置变化时漏算。

不可推断事项：

- 本环境没有真机/模拟器，无法直接确认用户设备上具体残留文件名或断网瓦片加载行为。
- 无法从本地代码判断用户当时是否打开了 `缓存视野`，以及是否使用默认 `builtin:openstreetmap` 还是自定义 style URL。

## 方案取舍

采用最小修复，不改设置页交互和文案：

- 清理流程改为：删除所有 offline regions -> 清 ambient cache -> `resetDatabase()` -> `packDatabase()`。
- 将反射调用改为直接调用 `OfflineManager.FileSourceCallback`，让 R8/编译期能看到这些 MapLibre 公共 API 引用。
- `totalBytes()` 的扫描根目录增加 `FileSource.getInternalCachePath(context)` 与 `FileSource.getResourcesCachePath(context)`，同时保留原有 app 私有目录扫描。
- 不做手动删除 MapLibre DB 文件。理由：MapLibre 已提供 `resetDatabase()`；直接删除 SDK 正在管理的数据库文件风险更高，可能破坏 FileSource 生命周期。

副作用评估：

- `resetDatabase()` 会清空本 App 的 MapLibre 资源数据库，符合「清除全部地图缓存」语义。
- 不影响本地轨迹缓存；轨迹点仍由 `TrackCacheRepository` 和 tracker DB 管理。
- 清理耗时可能比原来更长，因此保留现有 `TrackerSettingsFragment.clearOfflineMapCacheAsync()` 后台执行方式。

## 实施内容

修改文件：`gpslogger/src/main/java/com/mendhak/gpslogger/tracker/offline/MapLibreOfflineMapStore.java`

- 新增 `org.maplibre.android.storage.FileSource` 引用。
- 删除 `java.lang.reflect.Method` / `Proxy` 反射调用。
- 新增 `runFileSourceOperation(...)`，统一执行 MapLibre 文件源异步操作并等待回调。
- `enableAmbientCacheRetention()` 改为直接调用 `OfflineManager.setMaximumAmbientCacheSize(...)`。
- `clearAmbientCache()` 改为直接调用 `OfflineManager.clearAmbientCache(...)`。
- 新增 `resetDatabase()` 和 `packDatabase()` 包装。
- `deleteAll()` 改为依次执行 `deleteAllOfflineRegions()`、`clearAmbientCache()`、`resetDatabase()`、`packDatabase()`。
- `totalBytes()` 改为扫描 `mapCacheRoots()`，其中包含 MapLibre `FileSource` 的 internal/resources cache path。
