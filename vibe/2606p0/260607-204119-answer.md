### 2.2 联网核验（截至 2026-06-08）

- OSM Foundation Tile Usage Policy（`https://operations.osmfoundation.org/policies/tiles/`）：
  - 必须发送有效 `User-Agent` 标识应用与联系方式；
  - 禁止「批量下载」（Bulk downloading is strictly forbidden）；
  - 应用必须允许用户切换瓦片源；
  - 高流量应用会被封 IP。
- MapLibre Native Android 11.x 文档（`https://maplibre.org/maplibre-native/android/api/`）：
  - `Style.Builder().fromJson(...)` 支持纯 raster style；
  - **若 style 中没有任何 `background` layer，MapView 的默认底色就是黑色**（MapLibre 不会自动补一个浅色背景）；
  - `addOnDidFailLoadingMapListener` 只在 style 解析失败时触发，不在 tile 加载失败时触发；
  - `OfflineRegion` 创建必须传 `style URL`（不能传 raw JSON）；内置 raster 样式如果走「builtin:openstreetmap」这种自定义 schema，`OfflineManager` 是无法识别的，所以即便用户不切换样式，离线下载入口也得另起一条路径。
- OpenTopoMap Usage Policy（`https://opentopomap.org/about`）：明确禁止离线打包；移动端官方推荐 `OAM Maps` 等离线方案。

## 三、Bug 根因与修复方案

### 3.1 B1：轨迹地图打开后底图一片黑

**根因（已确认）**：内置 OSM style JSON 没有任何 `background` layer。MapLibre 在 raster tile 还没下载下来 / 下载失败时，画布默认就是黑色。一旦 `setStyle` 回调被触发（哪怕 tile 还没拿到），8 秒超时的兜底分支不会再生效（因为 `getStyle()` 不再为 null）。

**次要风险（待确认，但本次一并处理）**：

1. 首次进入 Fragment 时，`MapLibre.getInstance()` 与 `OpenStreetMapStyle.configureMapLibreHttpClient()` 在同一行被调用。MapLibre v11 的 `HttpRequestUtil.setOkHttpClient` 是全局静态，必须在「MapLibre 发起任何瓦片请求之前」就绪——目前顺序是 `getInstance → MapView 创建 → setStyle`，理论上 UA 注入能赶上瓦片请求，但仍有竞态隐患。修复时把 `configureMapLibreHttpClient` 抬到 `Application.onCreate`/`AppSettings` 静态初始化更稳。**本次方案**：保留原位置，但在 `MapLibreOfflineMapStore` 构造里也补一次（其实已经补了，见 `MapLibreOfflineMapStore.java:50`），并在轨迹地图 Fragment 入口提前一次，确保进入前一定生效。
2. tile 服务返回 4xx/5xx 时，没有任何错误提示渠道。修复中给 raster source 之外再叠一个 background layer 当兜底色，并保留 `tracker_track_map_no_basemap` 文案作为 status 提示（保持现有行为，无新增）。

**修复点**：

- 文件：`gpslogger/src/main/java/com/mendhak/gpslogger/tracker/offline/OpenStreetMapStyle.java`
- 在 `styleJson()` 输出里增加一个排在 raster 层之前的 background layer，背景色与 fallback 一致（`#E8EAED`，浅灰），解决「tile 加载中/加载失败时黑屏」的根因。
- 同步给 `attribution` 串末尾保留 OSM 信誉信息（已存在），不动。
- 不动 `tile.openstreetmap.org` URL、不动 User-Agent。

伪 JSON 形式（最终落到代码里仍然是 `+ "..."` 字符串拼接，与现有风格一致）：

```json
{
  "version": 8,
  "name": "OpenStreetMap Standard",
  "sources": { "osm-standard": { "type": "raster", "tiles": [...], "tileSize": 256, "minzoom": 0, "maxzoom": 19, "attribution": "© OpenStreetMap contributors" } },
  "layers": [
    { "id": "background", "type": "background", "paint": { "background-color": "#E8EAED" } },
    { "id": "osm-standard", "type": "raster", "source": "osm-standard", "paint": { "raster-opacity": 1.0 } }
  ]
}
```

**为什么不直接复用 fallback 路径**：fallback 没有 OSM raster，等于永久无图。我们要让用户能看到 OSM 在线底图，只是在 tile 未到位时不再是黑屏。

**回归风险**：极低。MapLibre style spec 明确支持 background 与 raster 并存，绘制顺序按数组顺序，background 在最底层。Attribution 不受影响。

### 3.2 B2：离线地图「下载当前视野」不直观

**根因**：当前实现根本没有「视野」概念。`OfflineMapManagerActivity` 是一个纯文字列表 Activity，没有任何 MapView；按钮逻辑（`onDownloadCurrentArea`）是「以最近一次定位为中心、5km × 5km 方框、缩放 8-15」。文案和按钮 ID 也对不上：按钮 ID 叫 `current_view`，文案写「Download 5 km radius」。用户的疑惑都正确：

1. 「视野」是什么？→ 当前是「最近定位点」，不是真正的地图视野；
2. 下载范围是什么？→ 仅靠 `tracker_offline_map_plan_format` 一行经纬度文字，不直观；
3. 放大到更高缩放还会加载更高分辨率吗？→ 不会，离线区域写死了 `maxZoom=15`，超出复用最近层级，这点文案有写但被埋没。

**修复方向（两层叠加，按改动小→大排序，本次都做）**：

#### 3.2.1 文案与按钮命名对齐

- 按钮文案改成：英文 `Download a region` / 中文 `下载一块离线区域`；
- 文案下方那行 `tracker_offline_map_plan_format` 已经存在，保留。
- 明确把「缩放级别」的含义、放大后行为单独提取出来用一个新 string `tracker_offline_map_zoom_explained`：

  英：`Higher max zoom = more detail but exponentially larger size. Zooming beyond max zoom shows enlarged tiles, no extra detail is fetched.`
  
  中：`最大缩放越高，细节越多但体积成指数增长。超出最大缩放只会放大已下载瓦片，不会自动下载更高分辨率。`

#### 3.2.2 给「计划下载范围」一个可视化（核心改动）

在 `OfflineMapManagerActivity` 顶部新增一个固定高度的 `MapView`，用一个 GeoJSON polygon 把「将要下载的 BBox」画上去，让用户一眼看见范围。交互能力压到最小：

- 不允许用户在这个 MapView 里手动拖拽改 BBox（首版避开「手动框选」复杂度）；
- 默认仍是「定位点为中心、可调半径」；
- 加一个 `半径 (km)` 的 `EditText` 或者 `SeekBar`：枚举 1 / 2 / 5 / 10 / 20 km（默认 5 km 保留向后兼容）；
- 加一个 `最大缩放` 的 `Spinner`：12 / 13 / 14 / 15 / 16 / 17（默认 15 保留向后兼容）；
- 调整后实时重画 polygon 与 `tracker_offline_map_plan_format` 文案。

**估算瓦片数 / 体积**（重要，避免用户误下 GB 级）：

- 给定 BBox 与 zoom range，瓦片数 ≈ Σ_{z=minZoom..maxZoom} (tilesX(z) * tilesY(z))；
- 单瓦片 ≈ 20 KB（OSM 标准 raster 平均），仅做提示，不做硬截断；
- 在文案里再加一行 `tracker_offline_map_size_estimate_format`：
  
  英：`Estimated tiles: ~%1$d, estimated size: ~%2$d MB.`
  
  中：`估算瓦片数：约 %1$d 个，估算体积：约 %2$d MB。`

#### 3.2.3 顺手开启「在轨迹地图直接下载视野」入口（次要）

在 `TrackMapViewFragment` 工具栏增加一个新按钮 `下载当前视野`：

- 取 `mapLibreMap.getProjection().getVisibleRegion().latLngBounds` 作为 BBox；
- 用当前相机 `zoom` 向上取整作为 `minZoom`，再加 `+2` 作为 `maxZoom`（上限不超过 17）；
- 跳到 `OfflineMapManagerActivity` 并预填 BBox / zoom，让用户最终确认。

这个入口能解决「我现在看的地图就是我想离线的范围」的最常见诉求，对用户更直观。**注意**：当前 `OpenStreetMapStyle.usesPublicOpenStreetMapTiles(...) == true` 时仍然走 `tracker_offline_map_public_osm_blocked` 路径，按钮直接 Toast 拒绝，不让用户误以为按一下就能离线。

**首版取舍**：3.2.1 + 3.2.2 必做；3.2.3 工作量稍大、需要在 Activity 间传 BBox/zoom 参数，作为次序靠后实施。如果时间紧，先只做 3.2.1 + 3.2.2。

### 3.3 B3：地图选型改成 OpenStreetMap 是否可行

**结论**：可行，且**当前默认底图已经是 OpenStreetMap 标准瓦片**（详见 `TrackerPreferenceNames.DEFAULT_OFFLINE_MAP_STYLE_URL = "builtin:openstreetmap"`，`OpenStreetMapStyle.styleJson()`）。所以 B3 的根本问题不是「能不能改」，而是「现状没看出来用了 OSM」——这正是 B1 黑屏导致的视觉错觉。修复 B1 后用户立刻能看见 OSM 底图。

**OSM 在线浏览**：可行，但要遵守 OSM Foundation Tile Usage Policy，重点：

1. 必须发送有效 `User-Agent`。**已实现**：`OpenStreetMapStyle.buildUserAgent`，含包名与 GitHub URL。
2. 禁止「batch / bulk」下载。这就是 `MapLibreOfflineMapStore.createRegion` 在样式为 OSM 公共瓦片时直接抛异常的原因——**已实现**。
3. 必须允许用户切换瓦片源。**已实现**：`offline_map_style_url` 是 EditTextPreference，用户可填自托管/付费服务 URL。

**OSM 离线**：**不可行**，至少不能直接用 `tile.openstreetmap.org`：

- OSM 官方瓦片明确禁止批量预取；
- OpenTopoMap 同样禁止离线打包；
- 想要「在 App 内一键离线」的合规路径有三条：
  - **自托管 OSM 瓦片**（用户/团队自己跑 `Switch2OSM`/`OpenMapTiles`），样式 URL 填自托管；
  - **付费服务商**（MapTiler / Stadia Maps / Thunderforest），按其 ToS 离线；
  - **改用 Mapsforge `.map` 离线矢量文件**（与上一版 answer 的「VTM 候选」一致）——这是真正脱离 tile policy 限制的路径，但需要引入新 SDK，本次不动。

**给用户的可行结论**：

| 场景 | 当前可用？ | 备注 |
| --- | --- | --- |
| 在有网时用 OSM 标准瓦片浏览 + 看轨迹 | ✅（修复 B1 后立刻可用） | 已配 UA，单用户合规 |
| 在轨迹地图上叠加轨迹颜色 | ✅ | 与 OSM 无关，纯 GeoJSON |
| 一键离线下载 OSM 标准瓦片 | ❌ | 与 OSM 政策冲突；UI 已主动阻止 |
| 一键离线下载自托管 / 付费服务瓦片 | ✅ | 用户在 `offline_map_style_url` 填自己的 style URL 即可 |
| 完全脱网情况下查看底图 | ⚠️ | 需要用户先用 ↑ 第 4 种方式预下载，本次不引入新 SDK |

**本次不引入**新底图 SDK（VTM、MapsForge），保持 MapLibre Native + OSM 在线 + 自托管/付费离线的现状。

## 六、验证说明

### 6.1 编译

`./gradlew :gpslogger:assembleDebug` 应当能编过。

### 6.2 黑屏修复

- 步骤：清空 App 数据 → 打开 App → 进入「轨迹地图」视图。
- 预期：进入瞬间地图区域是浅灰底色（`#E8EAED`），之后 OSM 瓦片逐步覆盖；中途切网时仅瓦片不再增加，但灰色背景始终在。
- 反例：若仍黑屏 → 应当不是 background layer 问题，而是 MapLibre 全部 style 加载失败，此时 `addOnDidFailLoadingMapListener` 应该已经回到 fallback；若仍黑，需要看 logcat `Track map style failed to load: ...`。

### 6.3 离线下载可视化

- 步骤：进入「管理离线地图区域」→ 调整「半径」与「最大缩放」滑块。
- 预期：
  - 顶部 MapView 上的红色矩形 polygon 实时改变大小；
  - 文案行同步更新 BBox 经纬度、缩放范围、瓦片数估算、体积估算；
  - 「最大缩放」改为更高值时，体积估算大致按 4 倍增长（每升一级，瓦片数 ×4）；
  - 当 `style URL = builtin:openstreetmap` 时，下载按钮仍然被 `tracker_offline_map_public_osm_blocked` 拦截，符合 OSM 政策。

### 6.4 OSM 一致性

- 在底图右下角应能看到 `© OpenStreetMap contributors`（MapLibre 会从 style 的 attribution 字段自动渲染）。
- 关网下重启 App，再次打开「轨迹地图」：背景灰、轨迹线在、状态条提示「该区域底图未缓存，仅显示轨迹」。

### 6.5 多语言对照

- 中英文版本下分别打开「管理离线地图区域」，确认新增字符串显示正常无 `?` / `<missing>` 占位。

## 七、待确认事项

1. **「下载视野」入口（3.2.3）** 是否首版纳入？目前文档把它列为可选；若用户希望「直接在轨迹地图上一键下载视野」是首要诉求，应放在本轮一并实现。
2. **半径与缩放枚举**：1/2/5/10/20 km 与 12-17 zoom 是基于经验取，是否调整由用户决定。
3. **背景色 `#E8EAED`** 是否合适：与 fallback 一致，可以根据视觉偏好换成更接近纸面的 `#F4F1EA`（OpenTopoMap 风格），不影响 OSM 政策。

### 9.4 B1 补丁第三轮（用户反馈「卡在瓦片加载缓慢」之后）

用户反馈：手机与电脑同一 Wi-Fi、其他 App 网络正常，但轨迹地图一直停在「瓦片加载缓慢…」文案。结合状态机意味着 style 已加载、`addOnDidBecomeIdleListener` 在 10 秒内未触发。两种可能：(a) MapLibre 没有发起瓦片 HTTP 请求，(b) MapLibre 发起了但 idle 信号在该机型上没有按预期推送。本轮在不动业务逻辑前提下，把诊断信号铺到能看到。

| # | 路径 | 变更摘要 |
| --- | --- | --- |
| 1 | `OpenStreetMapStyle.java` | `configureMapLibreHttpClient` 内：调用 `HttpRequestUtil.setLogEnabled(true)` 打开 MapLibre 内置 HTTP 日志；OkHttp 拦截器改为对每个请求记录 `LOG.info "MapLibre HTTP <method> <url> -> <code> (<ms> ms)"`，异常路径记录 `LOG.warn "MapLibre HTTP ... threw <exception>"`；安装成功/失败都打日志，便于 logcat 排查 |
| 2 | `TrackMapViewFragment.java` | 追加 `addOnDidFinishRenderingMapListener` 监听。`fully=true` 即「全部可见瓦片已完成渲染」，与 idle 等价但在 v11 部分机型更稳定。命中条件等同 idle 监听：hide 临时态状态文本。新增一行 `LOG.info "Track map finished rendering, fully={}"` |

#### 期望的现场表现

- **能看到 OSM 底图**：说明 idle 监听原本不及时，新加的 rendering 监听把警告及时清掉。
- **仍卡在「瓦片加载缓慢」**：用户用 `adb logcat -s "TrackMapViewFragment:*" "OpenStreetMapStyle:*" "Mbgl-*:*" "OkHttp:*"` 抓取，并粘回。重点看：
    - 有没有 `MapLibre HTTP GET https://tile.openstreetmap.org/...` 行？没有 → 我们配置的 OkHttp 拦截器没被调用，MapLibre 走了另一条 HTTP 通道，需要换 SDK 集成方式。
    - 有 `MapLibre HTTP ... -> 200`？→ 瓦片实际是拿到的，渲染侧没把 idle/rendering 事件抛上来，需要换其他事件或换 SDK 版本。
    - 有 `MapLibre HTTP ... threw <异常>` 或 `-> 4xx/5xx`？→ 服务端在该机型 IP 下拒绝，这种情况只有改瓦片源（自托管 / 付费服务商 / CartoDB）才行。

#### 不引入但讨论过

- **改成 CartoDB Voyager 默认**：会绕开 OSM Tile Policy 风险，但用户上一轮明确询问 OSM 是否可行，结论也是肯定可用，盲目切换会违背诉求。等用户提供 logcat 再决定是否新增一个备选 builtin 样式。
- **去掉自定义 OkHttp 拦截器**：理论上 MapLibre 默认 UA 也能被 OSM 接受，但拿不到 `MapLibre HTTP` 日志、无法定位问题，本轮保留拦截器但加日志。
