## 任务范围

本轮只处理 `260607-204119-prompt.md` 明确列出的两个 bug：

1. 打开「轨迹地图」视图，地图不加载，底层显示为一片绿色。
2. 配置页进入「管理离线地图区域」后卡死无响应。

未扩展实现新的旅游徒步功能，未调整 Custom URL Outbox、本地轨迹缓存或地图 SDK 选型。

## 依据与问题定位

### 轨迹地图

已确认代码路径：`gpslogger/src/main/java/com/mendhak/gpslogger/tracker/ui/TrackMapViewFragment.java`。

原实现只在 `mapView.getMapAsync(...)` 后执行：

- 从 `TrackerPreferenceHelper.getOfflineMapStyleUrl()` 读取样式 URL。
- 调用 `map.setStyle(new Style.Builder().fromUri(styleUrl), style -> refreshTrack(true))`。
- 只有样式成功加载后才绘制轨迹。

问题点：

- 没有设置初始相机位置。无轨迹或相机默认位置不在用户轨迹附近时，用户容易看到默认底色/远景，误判为地图未加载。
- 没有处理样式加载失败、网络慢、样式 URL 不可达的分支。MapLibre 官方 API 说明 `setStyle` 失败会触发 `MapView.OnDidFailLoadingMapListener`，而 `Style.Builder.fromJson(...)` 支持从本地 JSON 样式加载；本轮据此增加失败/超时兜底。
  - 官方依据：https://maplibre.org/maplibre-native/android/api/-map-libre%20-native%20-android/org.maplibre.android.maps/-map-libre-map/set-style.html
  - 官方依据：https://maplibre.org/maplibre-native/android/api/-map-libre%20-native%20-android/org.maplibre.android.maps/-style/-builder/index.html

### 离线地图区域管理页

已确认代码路径：

- `gpslogger/src/main/java/com/mendhak/gpslogger/tracker/ui/OfflineMapManagerActivity.java`
- `gpslogger/src/main/java/com/mendhak/gpslogger/tracker/offline/MapLibreOfflineMapStore.java`

原实现中：

- `OfflineMapManagerActivity.onCreate()` 直接调用 `refresh()`。
- `refresh()` 在主线程调用 `store.listRegions()`。
- `MapLibreOfflineMapStore.listRegions()` 内部使用 `CountDownLatch.await(5, TimeUnit.SECONDS)` 把 MapLibre 的异步 `listOfflineRegions(...)` 包装成同步结果。
- `onDownloadCurrentArea()` 也在主线程调用 `store.createRegion(...)`，该方法内部同样使用 `CountDownLatch.await(5, TimeUnit.SECONDS)`。

结论：主线程等待 MapLibre 异步回调是进入页面卡死的直接原因，最坏情况下每次进入/创建区域都可阻塞约 5 秒。

## 实施内容

### 1. 修复轨迹地图样式加载与绿色底层问题

修改文件：`gpslogger/src/main/java/com/mendhak/gpslogger/tracker/ui/TrackMapViewFragment.java`

改动：

- 打开地图后先移动相机：优先使用最近本地轨迹点，其次使用当前 Session 位置，最后退回世界视图。
- 增加 `MapView.addOnDidFailLoadingMapListener(...)`，样式加载失败时切换到本地空白 fallback style。
- 增加 8 秒样式加载超时兜底，避免网络无响应时一直停在底色状态。
- fallback style 采用内置 JSON，不依赖网络；底图不可用时仍调用 `refreshTrack(true)` 绘制本地轨迹，并显示 `tracker_track_map_no_basemap`。
- 销毁 Fragment view 时清空 `mapLibreMap` 引用，避免延迟回调在视图销毁后继续操作 MapView。

取舍：

- 没有额外引入 raster tile 源或新的默认在线地图服务，避免新增瓦片授权/流量策略风险。
- fallback 只保证轨迹层可见并提示底图不可用，不伪装成完整底图。

### 2. 修复离线地图管理页卡死

修改文件：`gpslogger/src/main/java/com/mendhak/gpslogger/tracker/ui/OfflineMapManagerActivity.java`

改动：

- 新增单线程 `ExecutorService`，将 `listRegions()`、`createRegion()`、`delete()`、`deleteAll()` 调用移出 UI 线程。
- 主线程只做状态文案、按钮可用性、Toast 和列表渲染。
- 增加 `runIfAlive(...)`，Activity 销毁或 finishing 后不再更新 UI。
- 删除操作后延迟刷新列表，避免 MapLibre delete API 的异步删除尚未完成就立刻读到旧列表。
- 列表加载/创建/删除期间禁用按钮和列表，避免重复点击叠加任务。
- 支持 actionbar 返回按钮。

取舍：

- 保留 `MapLibreOfflineMapStore` 当前同步包装接口，减少本轮改动面；Activity 层保证不再从主线程调用这些同步方法。
- 未重构 `OfflineMapStore` 为全异步接口，避免牵连现有抽象和调用方。
