# 轨迹与地图最大地图缓存大小实施记录

生成时间：2026-06-13

## 依据来源

- 本轮任务：`vibe/2606p0/260613-142352-prompt.md`，要求在「轨迹与地图」配置中新增最大地图缓存大小，默认 1G，缓存超上限时清理最旧缓存。
- 前序现状：`vibe/2606p0/260612-235821-answer.md` 记录上一轮移除了旧的「离线地图缓存上限」配置，并保留「已缓存地图文件大小」与「清除全部地图缓存」。
- 当前设置页：`gpslogger/src/main/res/xml/pref_tracker.xml` 的离线地图分类已有 `tracker_offline_map_cache_size`、`tracker_clear_offline_map_cache`、`offline_map_style_url`。
- 偏好集中定义：`TrackerPreferenceNames.java`、`TrackerPreferenceHelper.java`。
- 地图缓存统计与清理：`MapLibreOfflineMapStore.totalBytes()` 通过 `maplibre`、`mapbox`、`mbgl` 命名特征统计 app 私有目录中的地图缓存；`deleteAll()` 删除 MapLibre offline regions 后清理 ambient cache。
- 轨迹地图缓存入口：`TrackMapViewFragment.cacheVisibleRegionIfEnabled()` 在「缓存视野」开启时调用 `MapLibreOfflineMapStore.enableAmbientCacheRetention()`，非公共 OSM 样式下会创建 MapLibre offline region。

## 需求拆解与方案

1. 新增用户配置：在「轨迹与地图」->「离线地图」分类新增 `最大地图缓存大小`，默认 `1 GB`。采用 `ListPreference`，候选值为 256 MB、512 MB、1 GB、2 GB、5 GB、10 GB，避免自由输入导致非法值。
2. 偏好读取：新增 `OFFLINE_MAP_MAX_CACHE_MB` 和 `DEFAULT_OFFLINE_MAP_MAX_CACHE_MB = 1024`，`TrackerPreferenceHelper` 统一提供 MB 和 bytes 读取方法。
3. ambient cache：`enableAmbientCacheRetention()` 不再设置 `Long.MAX_VALUE`，而是把 MapLibre `setMaximumAmbientCacheSize(...)` 设置为用户配置的上限。
4. offline region / 文件兜底清理：新增 `trimToLimit(...)` / `trimToConfiguredLimit()`。当总地图缓存超过上限时，先按 MapLibre offline region id 从小到大删除，作为“最旧 region”的可确认近似；仍超限时，再按文件 `lastModified` 从旧到新删除匹配到的地图缓存文件。
5. 触发点：用户调整上限时立即异步裁剪并刷新已缓存大小；MapLibre offline region 下载完成时自动裁剪；轨迹地图「缓存视野」开启时同步应用 ambient cache 上限。

## 待确认 / 风险

- 未能在本环境完成 Android 编译和真机验证，原因是缺少 Java/JDK。
