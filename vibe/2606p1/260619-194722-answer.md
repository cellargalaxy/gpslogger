# 轨迹地图地名搜索实施记录

## 结论

已让「轨迹地图」支持通过地名搜索，并按最新 prompt 优化了地图顶部操作栏布局。

本轮按任务要求采用 OSM Nominatim 方案：手机端直接请求 Nominatim-compatible search endpoint，解析返回的地名候选结果，用户选择后移动 MapLibre 相机并在命中位置绘制红色圆点。

顶部操作栏已改为“左侧分类下拉框 + 右侧当前分类操作区”：

- 控制：刷新、定位到最新点、适应轨迹边界。
- 配置：图层切换、缓存视野。
- 搜索：地名输入、搜索按钮。
- 只有当前选中的分类操作区可见。

## 依据来源

- 任务来源：`vibe/2606p1/260619-194722-prompt.md`，要求：
  - 地图支持通过地名搜索。
  - 采用 OSM Nominatim。
  - 个人手动搜索，并发不会高。
  - 没有服务端，只有手机端。
  - 优化地图顶部操作栏布局：左侧添加分类下拉框；控制、配置、搜索分类展示；仅显示当前分类的具体操作。
- 当前地图页：`gpslogger/src/main/java/com/mendhak/gpslogger/tracker/ui/TrackMapViewFragment.java`，原有功能包括 MapLibre 初始化、轨迹绘制、定位到最新点、图层切换、缓存视野。
- 当前布局：`gpslogger/src/main/res/layout/fragment_track_map_view.xml`，原先无地名输入框或搜索按钮。
- 当前网络依赖：`gpslogger/build.gradle` 已有 `com.squareup.okhttp3:okhttp:3.10.0`，无需新增依赖。
- 当前权限：`gpslogger/src/main/AndroidManifest.xml` 已有 `android.permission.INTERNET`，无需新增权限。
- OSMF Nominatim Usage Policy（`https://operations.osmfoundation.org/policies/nominatim/`）确认：
  - 公共服务绝对上限为 1 request/second。
  - 必须提供有效 User-Agent 或 Referer。
  - 必须显示 attribution。
  - 用户直接触发的搜索可以接受，但 App 总流量仍受限制。
  - App 应能切换服务，最好通过代理和缓存；本轮无服务端，因此增加手机端可配置 endpoint 作为可切换兜底。
  - 禁止 autocomplete、系统性查询、批量 geocoding。

## 方案取舍

采用“手机端直连 Nominatim + 手动触发 + 可配置 endpoint”的最小方案。

- 不做自动补全：避免违反 Nominatim 公共服务禁止 autocomplete 的约束。
- 不做后台批量请求：搜索只由用户点击搜索按钮或键盘搜索动作触发。
- 请求节流：同一地图页内搜索间隔至少 1 秒，且同一时间只允许一个请求在飞。
- User-Agent：复用并公开 `OpenStreetMapStyle.buildUserAgent(...)`，格式为 `GPSLogger-Travel/<version> (<package>; https://github.com/mendhak/gpslogger)`。
- Attribution：搜索结果弹窗标题显示 `OpenStreetMap`。
- 可切换 endpoint：新增「轨迹与地图」设置项 `track_map_nominatim_search_url`，默认 `https://nominatim.openstreetmap.org/search`；用户可改为自托管或第三方 Nominatim-compatible endpoint。
- 操作栏分类：用 `Spinner` 承载分类选择，避免顶部横向堆满按钮；右侧用三个 `LinearLayout` 分别承载控制、配置、搜索，只切换可见性，不改变原按钮业务逻辑。

## 改动点

### 1. `TrackMapViewFragment.java`

- 新增地名搜索入口绑定：
  - `track_map_search_text`
  - `track_map_btn_search`
- 新增 `searchPlace(...)`：
  - 空输入提示。
  - 地图未准备好提示。
  - 请求中禁止并发搜索。
  - 1 秒内重复搜索提示等待。
  - 使用 OkHttp 异步请求 Nominatim，不阻塞 UI。
  - Header 带 `User-Agent`、`Accept: application/json`、`Accept-Language`。
- 新增 `buildNominatimSearchUrl(...)`：
  - 从 `TrackerPreferenceHelper.getTrackMapNominatimSearchUrl()` 读取 endpoint。
  - 自动拼接 `format=jsonv2&limit=5&q=...`。
  - 支持 endpoint 已含 query string 的情况。
- 新增 `parseNominatimResults(...)`：
  - 解析 JSON array 中的 `lat`、`lon`、`display_name`。
- 新增 `showSearchResults(...)`：
  - 无结果提示。
  - 单结果直接跳转。
  - 多结果弹窗选择。
- 新增 `addOrUpdateSearchResultMarker(...)`：
  - 搜索命中位置绘制红色 halo + dot。
- `onDestroyView()` 中取消仍在飞的搜索请求。

### 2. 地图布局和图标

- `fragment_track_map_view.xml`：
  - 顶部左侧新增 `track_map_toolbar_mode` 下拉框。
  - 右侧新增三个操作组：
    - `track_map_toolbar_controls`：刷新、定位到最新点、适应轨迹边界。
    - `track_map_toolbar_config`：图层切换、缓存视野。
    - `track_map_toolbar_search`：地名输入框、搜索按钮。
  - 默认展示控制类；切换下拉项时只展示对应分类操作组。
- 新增 `gpslogger/src/main/res/drawable/ic_track_map_search.xml` 搜索图标。

### 3. 设置项

- `TrackerPreferenceNames.java`：
  - 新增 `TRACK_MAP_NOMINATIM_SEARCH_URL`。
  - 新增默认值 `DEFAULT_TRACK_MAP_NOMINATIM_SEARCH_URL`。
- `TrackerPreferenceHelper.java`：
  - 新增 `getTrackMapNominatimSearchUrl()`。
  - 仅接受 `http://` / `https://`，否则回退默认 endpoint。
- `pref_tracker.xml`：
  - 在「轨迹地图」分类新增 `EditTextPreference`：`track_map_nominatim_search_url`。
- `TrackerSettingsFragment.java`：
  - 新增 `EditTextPreference` summary 绑定和修改后更新。

### 4. 文案

- `values/strings.xml`、`values-zh-rCN/strings.xml` 新增：
  - 搜索按钮/输入框/状态提示。
  - 搜索结果弹窗标题。
  - Nominatim endpoint 设置项标题和说明。
  - 操作栏分类数组 `tracker_track_map_toolbar_mode_entries`：控制/配置/搜索。

## 影响评估

- 轨迹数据链路不变：不影响 `TrackCacheRepository.queryRange(...)`、轨迹切段、当前位置点、图层切换、离线地图缓存。
- 操作栏只改变展示分组，不改变刷新、定位、适应边界、图层切换、缓存视野等既有操作行为。
- 网络行为明确：只在用户手动搜索时请求，非自动补全，非批量。
- 公共 Nominatim 风险：
  - 仍是公共服务，策略可能变化；已通过可配置 endpoint 降低硬编码风险。
  - 无服务端代理，因此不能做跨设备共享缓存；当前定位为个人手动低频使用。
- 隐私风险：
  - 用户输入的地名会发送给配置的 Nominatim endpoint。
  - 不会自动发送当前位置或轨迹点。
