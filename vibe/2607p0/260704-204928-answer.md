# 轨迹地图新增「叠加 KML 轨迹」功能

## 一、背景与现状（依据来源）

- 视图：`TrackMapViewFragment.java`（`com.mendhak.gpslogger.tracker.ui`）+ 布局 `res/layout/fragment_track_map_view.xml`。
- 顶部工具栏范式（前次任务 `260704-201356-answer.md` 已落地并与代码核对一致）：
  - 左侧 `Spinner @id/track_map_toolbar_mode` 切换模式，常量 `TOOLBAR_MODE_CONTROLS/CONFIG/SEARCH/TRACK = 0/1/2/3`（`TrackMapViewFragment.java:99-102`）。
  - 右侧按模式显示 4 组子工具栏之一：`track_map_toolbar_controls / _config / _search / _track`（`applyToolbarMode()` `TrackMapViewFragment.java:208-214`）。
  - 「轨迹」模式 `track_map_toolbar_track` 内当前仅一个铺满宽度的分段下拉 `Spinner @id/track_map_track_selector`（布局 `fragment_track_map_view.xml:138-153`）。
- 历史轨迹渲染：`refreshTrack()` 拉点 → `TrackSegmenter.segment()` 切段 → 每段一个 `LineLayer`，`lineColor=colorForIndex()`、`lineWidth=4`、`lineOpacity=0.9`（`TrackMapViewFragment.java:672-698`）；图层/源 id 记录在 `currentLayerIds/currentSourceIds`。
- 存放路径来源：`PreferenceHelper.getInstance().getGpsLoggerFolder()`，默认 `Files.storageFolder()` = `context.getExternalFilesDir(null)`（应用专属外部目录，读写**无需运行时权限**）（`PreferenceHelper.java:325-328`、`Files.java:119-124`）。
- 项目既有 XML 读取风格：`GpxReader.java` 用 `DocumentBuilderFactory`（默认非命名空间感知）DOM 解析，按标签名检索（`GpxReader.java:49-117`）。
- KML 样例（`vibe/2607p0/2023-06-17 0412鹰鸽嘴峰.kml`）实测结构：
  - 折线在 `TbuluTrackFolder` 下的 9 个 `<Placemark><gx:Track>`，每点一个 `<gx:coord>lon lat alt</gx:coord>`（空格分隔，样例 `:392-393`）。
  - 另有 `<Point><coordinates>lon,lat,alt</coordinates>` 标注点（起点/终点/露营点等），非路径。
  - 标准 KML 亦可能用 `<LineString><coordinates>lon,lat[,alt] …</coordinates>`（样例未出现，但为通用格式一并支持）。

## 二、需求与目标

- 在「轨迹」下拉区新增一个控件，选择**一个或多个** KML 文件，把其中的**路径**画到地图上。
- KML 路径需与历史轨迹**明显区分**，且多个 KML 路径之间也需**互相区分**。

## 三、方案取舍

### 交互控件：按钮 + 预加载多选对话框（而非纯 Spinner，也非系统文件选择器）

需求内含冲突：用户「偏向下拉框」，但又要求「一个或多个」多选——原生 `Spinner` 只能单选，无法多选。取其本质诉求「**预先加载可用 KML、免去手动翻目录**」，最终采用：

- 在「轨迹」子工具栏分段下拉右侧新增一个 `ImageButton @id/track_map_btn_kml`（与工具栏既有图标按钮范式一致，48dp）。
- 点击弹出**多选对话框**（`AlertDialog.setMultiChoiceItems`），条目 = 约定目录下预扫描到的 `*.kml` 文件；已展示的文件回显为勾选态；每条前置该文件的色块（`■`，颜色与地图上一致）。
- 取「下拉框」的核心优点（预加载、免翻找），同时支持多选；不采用系统 SAF 文件选择器（正是用户点名的「每次选文件麻烦」缺点）。

未采用：把 KML 混入现有分段 `Spinner`——会牵动 `applySegmentSelection()` 单选高亮逻辑，改动大且语义混淆。

### 约定存放路径

`<gpslogger_folder>/kml/`（`gpslogger_folder` 默认应用外部专属目录，读写无需权限）。目录不存在时自动 `mkdirs()`；为空时对话框提示完整路径，引导用户放入文件。**不新增偏好项**（改动最小）。

### 渲染区分

- 历史轨迹：实线、`lineWidth=4`、多分段循环上色（不变）。
- KML 路径：**虚线**（`lineDasharray {2,2}`）+ 更粗（`lineWidth=5`）+ 圆角端点 → 与历史实线一眼可辨。
- 多个 KML 互相区分：每个文件按其在**排序后文件列表**中的下标取 `KML_PALETTE` 颜色（确定性映射，故对话框色块与地图线同色）；同一文件的多段共用该文件色。

### 解析

新增 `KmlTrackReader`（仿 `GpxReader` 的 DOM 风格）：非命名空间感知 DOM，直接检索 `gx:Track`(其 `gx:coord`) 与 `LineString`(其 `coordinates`)，产出 `List<List<double[]>>`（每条折线为 `{lat, lon}` 序列，点数 <2 丢弃）。忽略 `<Point>` 标注点（非路径）。解析在后台线程（复用 `offlineMapExecutor`），图层增删在地图线程（`postToMapView`）。

## 四、实施步骤

1. `KmlTrackReader.java`（新增）：解析 KML 折线。
2. `drawable/ic_track_map_kml.xml`（新增）：两端圆点 + 中间虚线的「虚线轨迹」矢量图标（呼应 KML 虚线渲染）。
3. 布局 `fragment_track_map_view.xml`：`track_map_toolbar_track` 内分段 Spinner 改 `0dp weight=1`，其后加 `ImageButton @id/track_map_btn_kml`。
4. `strings.xml` / `values-zh-rCN/strings.xml`：新增 KML 相关文案。
5. `TrackMapViewFragment.java`：常量/字段、按钮接线、`showKmlChooser()`、`applyKmlSelection()`、`renderKmlOverlays()`、`removeKmlLayers()`、目录/文件/配色辅助、内部类 `KmlPick/KmlRender`、新增 import。

## 五、副作用评估

- KML 图层用独立 id 前缀（`kml_track_layer_/source_`），与历史轨迹图层解耦；`refreshTrack()`（刷新/适应边界）不触碰 KML 图层，故历史刷新时 **KML 叠加保持**。
- 已知边界：切换底图图层会 `setStyle` 重建样式、清空所有图层（含 KML）；此时对话框仍回显勾选，重新「确定」即可重绘（已在文案/行为上可自恢复）。
- 读取仅限应用外部专属目录，无需新增权限；解析在后台线程，UI 不阻塞。
- 与主链路（定位/上传/缓存）无耦合。

## 验证结果

环境无 Android SDK（`ANDROID_HOME` 空、`~/Android/Sdk` 不存在、无 `javac`），无法执行 Gradle 全量编译；改以静态核对 + 逻辑校验（与前次任务同法）：

- **XML 合法性**：`fragment_track_map_view.xml`、`drawable/ic_track_map_kml.xml`、`values/strings.xml`、`values-zh-rCN/strings.xml` 四文件 XML 解析均通过（`OK`）。
- **资源引用闭环**：
  - Java 引用的 7 个 `R.string.tracker_track_map_kml_*` 在默认与 zh-rCN 两语种**均已齐备**（逐一对齐一致）。
  - `R.id.track_map_btn_kml` 在布局 `@+id` 定义；`@drawable/ic_track_map_kml`、`@string/tracker_track_map_kml_overlay`（按钮 contentDescription）均存在。
- **符号闭环**（`TrackMapViewFragment.java`）：`showKmlChooser/applyKmlSelection/renderKmlOverlays/removeKmlLayers/getKmlFolder/listKmlFiles/kmlColorForIndex` 及内部类 `KmlPick/KmlRender` 均定义且被引用；新增 import `java.io.File`、`java.util.Arrays`、`common.PreferenceHelper`、`maplibre…layers.Property` 到位。
- **括号平衡**：`TrackMapViewFragment.java`（`{}`=246、`()`=931、`[]`=36）与 `KmlTrackReader.java`（`{}`=22、`()`=67）左右均衡。
- **解析逻辑校验**（用样例 KML 模拟 reader 的字面标签检索）：`gx:Track` 命中 9、`LineString` 0（无重复计数）；共 2738 点、0 个无法解析；首点解析为 `{lat=31.002173, lon=102.8460751}`，与源文件 `<gx:coord>102.8460751 31.002173 …</gx:coord>` 的 lon/lat 次序一致，佐证 `parseSpaceCoord` 产出 `{lat,lon}`、经 `toGeoJsonLineString`（取 `ll[1]`=lon、`ll[0]`=lat）得到正确 GeoJSON `[lon,lat]`。
- **逻辑校验**：
  - KML 图层用独立前缀 `kml_track_layer_/source_`，`refreshTrack()` 只清 `currentLayerIds/currentSourceIds`，故历史刷新不影响 KML 叠加。
  - 后台线程仅解析 + 拼 GeoJSON（`toGeoJsonLineString` 为纯字符串运算，无视图访问）；增删图层与相机操作经 `postToMapView` 回到地图线程。
  - 颜色映射由「文件在排序列表中的下标」决定（`kmlColorForIndex`，`Math.floorMod` 环取），故对话框色块与地图线同色，且多文件互不相同；虚线（`lineDasharray{2,2}`）+ 更粗（5）令 KML 与历史实线（宽 4）一眼可辨。
  - 空选择 → `removeKmlLayers` + 「已清除」；有选择但无可绘线 → 「未找到轨迹路径」；部分文件失败 → 「部分失败」；成功 → 「已叠加 N 个」。

## 使用说明（约定）

把 `.kml` 文件放入 `<gpslogger_folder>/kml/` 目录（`gpslogger_folder` 见 GPSLogger 常规设置，默认应用外部专属目录）。进入「轨迹地图」→ 顶部模式选「轨迹」→ 点右侧 KML 按钮 → 勾选一个或多个文件 → 确定，即以彩色虚线叠加显示，并自动适应到其范围。取消全部勾选并确定可清除叠加。

# 追加需求：文件管理器「用 GPSLogger 打开 KML」→ 导入并展示

## 一、需求
在文件管理器点开 `.kml` 时，「打开方式」里出现 GPSLogger；选它后：把该 KML 复制到 `<gpslogger_folder>/kml/`，跳到「轨迹地图」并在地图上展示该路径。

## 二、方案（依据来源与取舍）
沿用项目既有的「独立半透明中转 Activity 处理 VIEW 链接」范式（`ProfileLinkReceiverActivity` + 其 manifest intent-filter），**改动最小、复用优先**：

1. **新增 `KmlImportActivity`（`tracker.ui`，半透明 `Theme.AppCompat.Translucent`、`excludeFromRecents`）**：
   - 从 `getData()`（`ACTION_VIEW`）或 `EXTRA_STREAM`（`ACTION_SEND`）取 URI。
   - 后台线程用 `ContentResolver.openInputStream` + `Streams.copyIntoStream`（复用既有工具，自动关流）把内容写入 `<gpslogger_folder>/kml/<显示名>.kml`；文件名优先取 `OpenableColumns.DISPLAY_NAME`，回退路径末段，做安全字符过滤并补 `.kml` 后缀；**同名覆盖**（幂等，避免重复导入堆副本）。
   - 成功：`TrackerPreferenceHelper.setPendingKmlImportName(name)` 暂存文件名 → 启动 `GpsMainActivity` 带 `IntentConstants.SHOW_TRACK_MAP=true` → `finish()`；失败弹 Toast。
2. **Manifest 注册 `KmlImportActivity`**：两条 `VIEW` intent-filter——① `content`/`file` + MIME `application/vnd.google-earth.kml+xml`；② 兜底 `content`/`file` + `host=*` + `*/*` + `pathPattern=.*\.kml`（应对把 MIME 报成 `*/*`/`octet-stream` 的管理器）。
3. **`GpsMainActivity` 路由**：`onCreate` 末尾与新增 `onNewIntent`（`singleTask` 复用实例走这里）调用 `handleShowTrackMapIntent()`：若带 `SHOW_TRACK_MAP` 则 `loadFragmentView(5)` 切到轨迹地图并 `removeExtra` 防重复；**不改用户默认视图偏好**（本次启动生效）。
4. **`TrackMapViewFragment` 消费**：`onCreateView` 读取并清空 `getPendingKmlImportName()` → 存 `pendingKmlFileName`；`refreshTrack()` 在（地图/样式就绪后）调用 `autoDisplayPendingKml()`——在 kml 目录按名找到该文件、按下标取色、复用 `applyKmlSelection()` 展示；**一次性**（消费即置空），放在历史空点早退之前，保证无历史轨迹也能展示 KML。
5. 文案：`tracker_track_map_kml_imported`、`tracker_track_map_kml_import_failed`（默认 + zh-rCN）。常量 `IntentConstants.SHOW_TRACK_MAP`、偏好 `TrackerPreferenceNames.PENDING_KML_IMPORT_NAME` + Helper 读/写/清。

未采用：直接给 `GpsMainActivity`（`singleTask`+`clearTaskOnLaunch`）挂 VIEW 过滤器——与其启动模式/清栈语义纠缠，且混淆职责。

## 三、副作用与已知边界
- 一次性偏好传参：`onCreateView` 读后立即清空，避免下次进轨迹地图误重放。
- `SHOW_TRACK_MAP` 消费后 `removeExtra`，避免配置变化/重建重复切视图；只影响本次启动，不改用户默认视图。
- content URI 读权限随中转 Activity 存活有效，复制完成（UI 线程 `finish()` 前）才结束，权限不失效。
- 与首个功能同一约定：KML 目录基于 `getGpsLoggerFolder()` 的**文件系统路径**；若用户把目录设成 SAF `content://` 树，`new File(base,"kml")` 不成立，导入会失败并 Toast（与 KML 选择器一致的既有假设）。

## 四、验证结果（追加，静态核对）
- XML：`AndroidManifest.xml`、两语种 `strings.xml` 解析通过（`OK`）。
- 引用闭环：`SHOW_TRACK_MAP`（定义于 `IntentConstants`；`KmlImportActivity` put、`GpsMainActivity` read/remove）、`PENDING_KML_IMPORT_NAME` 与 `get/set/clearPendingKmlImportName`（`KmlImportActivity` set、`TrackMapViewFragment` get+clear）、3 条 KML 文案两语种齐备、`KmlImportActivity` 已在 manifest 注册（`.tracker.ui.KmlImportActivity`）、其 import 全到位。
- 括号平衡：`KmlImportActivity`/`TrackMapViewFragment`/`TrackerPreferenceHelper` 均衡；`GpsMainActivity` 的 `{}` 差值 1 为 **HEAD 既有**（字符串字面量内 `{`，与本次改动无关，`git show HEAD` 同值）。
