# 轨迹图例迁移为顶部「轨迹」下拉

## 一、背景与现状（依据来源）

- 视图入口：`GpsMainActivity.java:1063` → `TrackMapViewFragment.newInstance()`。
- 布局：`res/layout/fragment_track_map_view.xml`
  - 顶部一行工具栏：左侧 `Spinner @id/track_map_toolbar_mode`（模式选择），右侧按当前模式展示三组子工具栏之一：
    - `track_map_toolbar_controls`（刷新/定位/适应边界）
    - `track_map_toolbar_config`（图层/缓存视野开关）
    - `track_map_toolbar_search`（地名搜索）
  - 中部 `FrameLayout @id/track_map_container`（MapView + 顶部居中状态文案 `track_map_status`）
  - **底部** `HorizontalScrollView` > `LinearLayout @id/track_map_legend`：一行可横向滚动的图例。
- 逻辑：`TrackMapViewFragment.java`
  - `refreshTrack()` 拉点 → `TrackSegmenter.segment()` 切段 → 每段一个 `LineLayer`（`colorForIndex()` 上色，`lineOpacity=0.9`）；同时 `addLegendChip()` 在底部生成一个「■ HH:mm - HH:mm」彩色 `TextView` 图例。
  - `addLegendChip()`：点击图例 → 切换 `selectedSegmentIndex` → `applySegmentSelection()`。
  - `applySegmentSelection()`：选中某段时该段 `lineOpacity=0.9`、其余 `0.22`；未选中（`ALL_SEGMENTS_SELECTED`）时全部 `0.9`；同时改图例文字透明度/背景。
  - 模式切换：`setupToolbarModeSelector()` / `applyToolbarMode()`，常量 `TOOLBAR_MODE_CONTROLS/CONFIG/SEARCH = 0/1/2`。
- 模式条目文案：`string-array tracker_track_map_toolbar_mode_entries`，仅存在于 `values/strings.xml`（Controls/Settings/Search）与 `values-zh-rCN/strings.xml`（控制/配置/搜索），其余语种回退默认。

## 二、需求与目标

- 现状痛点（用户描述）：底部一行图例**可读性差**（彩色小字、横向滚动）且**不易操作**（点击小色块）。
- 目标：在地图**顶部新增「轨迹」下拉**，把图例迁移进该下拉；合理设计并实现。

## 三、方案取舍

沿用「顶部工具栏由 `track_map_toolbar_mode` 下拉切换子工具栏」的既有范式，**改动最小、复用优先**：

1. 在模式下拉新增第 4 个模式「轨迹」（`TOOLBAR_MODE_TRACK = 3`）。
2. 该模式的子工具栏 `track_map_toolbar_track` 内放一个铺满宽度的 `Spinner @id/track_map_track_selector`，即「轨迹下拉」。
3. 下拉项 = 「全部分段」+ 每个已渲染分段（`■`色块 + `HH:mm - HH:mm`）。选择项即等价于原图例点击：
   - 选「全部分段」→ `selectedSegmentIndex = ALL_SEGMENTS_SELECTED`（全部高亮）。
   - 选某分段 → `selectedSegmentIndex = 该段`（仅该段高亮）。
   - 复用现有 `applySegmentSelection()` 驱动地图图层不透明度，逻辑零改动。
4. 删除底部 `HorizontalScrollView`/`track_map_legend` 及 `addLegendChip()`。

可读性/易操作性提升点：
- 自定义适配器 `TrackOptionAdapter`：分段行「色块用段色 + 文字用主题前景色」，避免整行彩色小字导致的低对比；下拉行加大内边距/字号，点击目标更大。
- 收起态直接显示当前所选分段，一眼可知当前高亮的是哪段。

未采用：用 `AlertDialog` 单选列表（`showMapLayerChooser()` 那种）。它并非字面意义的「下拉」，且需额外触发按钮，偏离用户「顶部下拉」诉求。

## 四、实施步骤

### 布局 `fragment_track_map_view.xml`
- 顶部工具栏 `track_map_toolbar_search` 之后，新增 `track_map_toolbar_track`（`visibility=gone`），内含 `Spinner @id/track_map_track_selector`（宽度 `match_parent`、高 48dp，与其它控件一致）。
- 删除底部 `HorizontalScrollView` + `LinearLayout @id/track_map_legend`。
- 同步更新顶部注释。

### 文案（仅两处存在该 array 的语言，其余回退默认）
- `values/strings.xml`：数组追加 `<item>Track</item>`；新增 `tracker_track_map_track=Track`、`tracker_track_map_track_all=All segments`。
- `values-zh-rCN/strings.xml`：数组追加 `<item>轨迹</item>`；新增 `tracker_track_map_track=轨迹`、`tracker_track_map_track_all=全部分段`。

### 逻辑 `TrackMapViewFragment.java`
- 常量新增 `TOOLBAR_MODE_TRACK = 3`。
- 字段：删除 `legendBar`；新增 `trackSelector` / `trackAdapter` / `trackOptions` / `suppressTrackSelectionCallback`。
- `onCreateView`：获取 `track_map_toolbar_track`、`track_map_track_selector`，调用 `setupTrackSelector()`；`setupToolbarModeSelector()` / `applyToolbarMode()` 增加 track 子工具栏参数与可见性切换。
- 新增 `setupTrackSelector()` / `rebuildTrackSelector()`：构建下拉项并把选中项与 `selectedSegmentIndex` 双向对齐；`setSelection` 会异步回调，用 `suppressTrackSelectionCallback` 抑制自触发。
- `refreshTrack()`：去掉 `legendBar.removeAllViews()` 与 `addLegendChip()`；分段记录 `label` 文案，构建完成后 `applySegmentSelection()` 归一化选中态再 `rebuildTrackSelector()` 同步下拉；空轨迹分支也重建下拉（回落到「全部分段」）。
- `applySegmentSelection()`：删除图例样式相关代码，仅保留图层不透明度更新。
- 删除 `addLegendChip()` 与仅供其使用的 `withAlpha()`；移除 `RenderedSegment.chip`（改存 `label`）。
- 新增内部类 `TrackOption` / `TrackOptionAdapter` 与 `dp()` 辅助；移除不再使用的 `import android.graphics.Color`，新增 `SpannableStringBuilder/Spanned/ForegroundColorSpan`。

## 五、副作用评估

- 与主链路解耦不变，仅改「轨迹地图」视图内部；不涉及缓存/定位/上传链路。
- 选中态逻辑完全复用 `applySegmentSelection()`，行为等价，仅交互载体从「底部图例」变为「顶部下拉」。
- 移动端布局：底部图例移除后 MapView 竖向可用空间增加；顶部工具栏行高不变。
- 兼容性：模式数组新增项仅默认与 zh-rCN 两处；其它语种回退默认英文，无缺项崩溃风险。

## 六、验证说明

- 逻辑校验：见下「验证结果」。
- 静态检查：确认 `Color` 移除后无残留引用、无遗留 `legendBar/addLegendChip/chip` 引用、`R.id.track_map_track_selector` 等新增 id 均在布局中定义。

## 验证结果

环境无 Android SDK（`ANDROID_HOME`/`~/Android/Sdk` 均不存在），无法执行 Gradle 全量编译；改以静态核对 + 逻辑校验：

- **XML 合法性**：`fragment_track_map_view.xml`、`values/strings.xml`、`values-zh-rCN/strings.xml` 三个文件 XML 解析均通过（`OK`）。
- **无残留引用**：`grep legendBar|addLegendChip|withAlpha|\.chip|Color\.|track_map_legend|import android.graphics.Color` 于改后 `TrackMapViewFragment.java` 命中 0 处；旧图例相关代码与不再使用的 `Color` 导入已彻底移除。
- **新符号闭环**：`TOOLBAR_MODE_TRACK`、`trackSelector`、`trackAdapter`、`trackOptions`、`rebuildTrackSelector()`、`TrackOption`/`TrackOptionAdapter` 均已定义并被引用；布局新增 id `track_map_toolbar_track`/`track_map_track_selector` 与 Java `findViewById` 一一对应。
- **文案闭环**：`tracker_track_map_toolbar_mode_entries` 数组在默认与 zh-rCN 均补齐第 4 项（Track/轨迹），`tracker_track_map_track`、`tracker_track_map_track_all` 两键在两语种齐备；其它语种回退默认英文，无缺项风险。
- **逻辑校验**：
  - 选中态复用 `applySegmentSelection()`，与原图例点击行为等价（选中段 `lineOpacity=0.9`，其余 `0.22`；全部分段时均 `0.9`）。
  - `rebuildTrackSelector()` 以 `suppressTrackSelectionCallback` + `View.post` 抑制 `setSelection` 的自触发回调，并把 `selectedSegmentIndex` 回落到实际存在的选项，保证「刷新/空轨迹后段数变化」时下拉与选中态一致。
  - `refreshTrack()` 空轨迹分支亦调用 `rebuildTrackSelector()`，下拉回落为仅「全部分段」。

- `gpslogger/src/main/res/values/strings.xml`、`values-zh-rCN/strings.xml`：模式条目与新增文案。
